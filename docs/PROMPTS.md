## 开场：设定协作规则

```text
你现在是我的开发助手。我要重新实现课程大作业第一阶段：
用 MongoDB 做一个简化在线问卷系统。

工作目录是 D:\MongoDB\Project1_rebuild，原项目在 D:\MongoDB\Project1。
请遵守：
1. 每一步先说明计划，再动手；
2. 不要一次性生成整个项目；
3. 每完成一个模块，运行测试或启动应用验证；
4. 不要只说“完成”，要给出文件、命令和实际输出。
先回复“明白”，不要写代码。
```

## 第 1 步：读需求

```text
第一步，不写代码。请读取 D:\MongoDB\Project1\大作业一第一阶段.docx，
提取功能清单、数据实体、必做测试点、交付物和不明确之处。
```

**检查**：四种题型、三种跳转、匿名、重复提交、逐题保存、统计、多集合设计是否齐全。

## 第 2 步：锁定范围

```text
第二步，只做第一阶段。给出模块划分、路由清单、页面清单、目录结构，
并明确不做的功能。
```

**检查**：不把第二阶段功能混进来；模块与 `auth/surveys/fill/stats/logic` 对应。

## 第 3 步：设计集合

```text
第三步，设计 MongoDB schema：users、surveys、questions、responses 四个集合。
给出字段、类型、示例文档，并说明哪些内嵌、哪些引用及理由。
```

**检查**：选项和跳转规则内嵌题目；答案和 path 内嵌答卷；owner/respondent 用引用。

## 第 4 步：设计索引

```text
第四步，只设计索引。列出字段、唯一性、部分索引条件和它支持的查询。
覆盖用户名、公开链接、问卷列表、题目顺序、答卷状态、草稿唯一、统计答案。
```

**检查**：部分唯一索引只约束 `status=in_progress`，不阻止已提交答卷。

## 第 5 步：设计跳转

```text
第五步，设计数据驱动跳转：单选按选项，多选按选项/数量，数字按大小比较。
规则存 questions.jump_rules，按顺序匹配，第一条命中；目标只能是后续题目或 end。
给出规则结构、匹配算法、校验规则和三个例子。
```

**检查**：规则里没有写死题目；只允许向后跳；文本题不支持跳转。

## 第 6 步：列出校验

```text
第六步，列出所有服务端校验：注册登录、问卷字段、题目配置、答案、跳转规则、
发布条件、截止/关闭、重复提交、匿名去重、权限归属。
输出表格：场景、触发条件、错误提示、HTTP 状态码。
```

**检查**：前端限制只是体验，服务端校验才是可信边界。

## 第 7 步：搭骨架

```text
第七步，开始写代码，但只搭骨架：config.py、db.py、app.py、最小首页。
完成后启动 python app.py，把访问结果发给我。
```

**检查**：应用能启动；索引能创建；首页返回 200。

## 第 8 步：认证

```text
第八步，实现注册、登录、退出。密码用 Werkzeug 哈希；登录后清空旧 session；
未登录访问受保护页面跳转登录；所有 POST 校验 CSRF。
```

**检查**：数据库存哈希；重复用户名被拒绝；CSRF 生效。

## 第 9 步：问卷与题目

```text
第九步，实现问卷、题目、跳转规则管理。用户只能管理自己的问卷；
支持四种题型和各自配置；发布前至少一题；发布后锁定结构；
编辑选项时已有规则的选项 key 不能错位。
```

**检查**：越权 404；发布后不能加题；删除选项后清理失效规则。

## 第 10 步：填写流程

```text
第十步，实现填写：登录后开始、创建草稿、逐题保存、按规则跳转、检查、提交、放弃。
匿名提交移除 respondent_id，用 HMAC 保存去重标识；不允许重复提交时拦截；
并发开始不能创建多个草稿；旧页面重复提交要忽略。
```

**检查**：草稿实时保存；跳转真的跳过题目；匿名答卷没有用户 ID；重复提交被拒绝。

## 第 11 步：统计

```text
第十一步，用 MongoDB aggregation 实现统计：已提交数、单选/多选计数与占比、
文本回答分页、数字 avg/min/max。草稿不计入；百分比分母为实际回答该题的人数。
```

**检查**：统计与手工计算一致；文本答案能翻页看全；空数据不报错。

## 第 12 步：测试

```text
第十二步，编写 pytest：注册登录、权限隔离、问卷/题目、发布锁定、三种跳转、
答案校验、草稿/放弃、匿名/重复提交、统计、分页、CSRF。
每个用例独立测试库，结束后删除；断言页面内容或数据库状态。
```

**检查**：`python -m pytest tests -q` 全部通过。

## 第 13 步：E2E

```text
第十三步，写 tools/e2e_smoke.py，用 requests.Session 走真实 HTTP：
注册 → 建卷 → 加题 → 配跳转 → 发布 → 实名填写 → 匿名填写 → 提交 → 统计 → 清理。
每步打印 PASS/FAIL。
```

**检查**：真实 Cookie、CSRF、重定向；跳转被验证；统计同时有实名和匿名答案。

第十四步，根据当前代码生成 README、DESIGN、API、TESTING、REPORT、AI_LOG。
